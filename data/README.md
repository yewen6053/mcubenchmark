# MCU-CodeBench Task Set

This repository contains a seed MCU firmware benchmark and an expanded generated MCU-CodeBench task set for evaluating LLM-based MCU firmware code generation.

The original seed file is `tasks.jsonl`. It contains 80 code-generation tasks across:

- GPIO
- UART
- I2C
- SPI
- ADC
- PWM
- Timer
- Interrupt
- FreeRTOS/basic multitasking

The expanded benchmark is generated by:

```powershell
python scripts\generate_extended_tasks.py
```

This writes:

- `mcucodebench_tasks.jsonl`: 324 generated tasks covering 18 MCU firmware scenarios, 6 platform/framework targets, and balanced easy/medium/hard difficulty.
- `data/source_catalog.json`: public SDK/project references used as scenario and API grounding.
- `reports/mcucodebench_data_report.md`: data report with coverage, source review, inclusion guidance, evaluation gates, and remaining gaps.

Each line in the seed `tasks.jsonl` is one task with these fields:

- `id`: stable task id.
- `category`: primary MCU feature.
- `platform`: target chip/family.
- `framework`: expected SDK or HAL style.
- `difficulty`: `easy`, `medium`, or `hard`.
- `prompt`: natural-language generation request to give to an LLM.
- `constraints`: hardware/API/resource constraints that should be respected.
- `expected`: required behavior or generated artifacts.
- `evaluation`: suggested automated checks.
- `failure_modes`: common LLM failure types to label during analysis.

Expanded `mcucodebench_tasks.jsonl` records add:

- `scenario`: normalized MCU development scenario family.
- `source_refs`: IDs from `data/source_catalog.json`.

Suggested use:

1. Feed `prompt` plus `constraints` to a target model.
2. Compile the generated code with the target SDK/toolchain.
3. Record compile success, warnings, resource usage, and whether static rules pass.
4. For selected tasks, run on hardware or simulator and record behavior.
5. Label failure modes using the task's `failure_modes` hints.

Recommended metrics:

- Compile pass rate
- API correctness
- Peripheral behavior pass rate
- Resource fit rate
- Static-rule pass rate
- Repair success after compiler/static feedback
- Average repair rounds

Validation:

```powershell
python validate_tasks.py
python check_hw_consistency.py
python -m unittest tests.test_generate_extended_tasks
```

This is still a paper-oriented benchmark draft. Before submission, freeze board definitions, SDK versions, build commands, and reference implementations.
